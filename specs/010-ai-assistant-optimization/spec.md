# Feature Specification: AI助手能力优化与长期记忆

**Feature Branch**: `010-ai-assistant-optimization`
**Created**: 2026-06-17
**Status**: Draft
**Input**: User description: "优化当前AI助手的能力，使其在宠物用品，宠物知识领域有更强大的功能，首先优化现有工具，其次探索是否可以新增能力。此外在问产品的场景中，是否可以增加卡片的种类，或优化现有spu卡片的样式。实现后台类似于claudecode的dream机制，能够定时的提取用户的新增对话的内容，提取有用的信息，例如用户的问题，宠物的状况等，形成AI助手针对某个用户的长期记忆。并且该部分内容展示到我的页，用户可以点击查看AI助手对他的印象，且可以支持手动修改，长期记忆仅保留必要内容，500字符以内最合适。"

## Clarifications

### Session 2026-06-17

- Q: 长期记忆应如何默认启用？ → A: 默认开启长期记忆，在AI助手和我的页展示说明，用户可随时关闭。
- Q: 首个面向用户落地的新增AI能力选择哪一个？ → A: 换粮计划。
- Q: Dream长期记忆整理的默认节奏是什么？ → A: 每日批次整理，目标24小时内更新。
- Q: 用户应如何查看和编辑长期记忆？ → A: 按宠物状况、偏好预算、常问问题、注意事项分组编辑。
- Q: 长期记忆是否保留历史版本？ → A: 只保留当前有效记忆和最近更新时间，不保留可见历史版本。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 提升宠物用品与宠物知识问答能力 (Priority: P1)

用户在AI助手中询问宠物用品选购、宠物喂养、成分解读、常见护理知识时，AI能够更准确地理解意图，结合已有商品、评价、宠物档案和对话上下文给出可执行建议；当信息不足时，AI优先提出关键追问，而不是给出笼统或臆测的答案。

**Why this priority**: AI助手是本特性的核心入口。只有先提升基础问答与现有工具使用质量，后续卡片展示和长期记忆才能真正产生价值。

**Independent Test**: 使用一组覆盖宠物用品、宠物知识、商品比较、健康风险提示的典型问题测试AI助手，验证回答是否命中用户意图、是否引用合适商品或知识、是否在信息不足时追问。

**Acceptance Scenarios**:

1. **Given** 用户询问"三个月英短适合什么猫粮"，**When** AI助手回复，**Then** 回复应围绕幼猫、英短、猫粮选择要点展开，并优先给出适龄商品或明确说明缺少可推荐商品。
2. **Given** 用户询问"这款粮蛋白太高会不会软便"，**When** AI助手回复，**Then** 回复应解释蛋白、脂肪、换粮、个体耐受等因素，并提示观察症状和必要时就医。
3. **Given** 用户询问"预算100以内买猫砂"，**When** 当前商品信息不足以直接推荐，**Then** AI助手应追问猫砂类型、除臭/粉尘/结团偏好或说明筛选依据。
4. **Given** 用户提出疑似急症问题，**When** AI助手回复，**Then** 应给出紧急就医提示，避免替代兽医诊断。

### User Story 2 - 新增和优化商品问答卡片 (Priority: P1)

用户在AI助手中询问产品、品牌、成分或多商品比较时，回复中不只展示单一SPU卡片，而是根据问题类型展示更合适的卡片：单品卡、对比卡、推荐清单卡、成分/营养解读卡、追问卡等。现有SPU卡片也应更适合快速决策。

**Why this priority**: 产品问答是宠物用品小程序的高价值场景。卡片承载购买决策信息，优化卡片能直接提升用户理解商品和继续浏览的效率。

**Independent Test**: 分别输入单品咨询、两个商品比较、按预算推荐、成分解读、信息不足五类问题，验证AI回复是否展示正确卡片类型并包含关键决策信息。

**Acceptance Scenarios**:

1. **Given** 用户询问某个明确商品，**When** AI助手找到对应SPU，**Then** 展示优化后的SPU卡片，包含品牌、名称、适用宠物、分类、价格区间、核心优点/注意点和进入详情入口。
2. **Given** 用户询问"皇家和渴望哪个好"，**When** AI助手识别为比较问题，**Then** 展示商品对比卡，突出适用阶段、主要差异、价格区间、优缺点和适合人群。
3. **Given** 用户询问"推荐几款适合幼猫的粮"，**When** AI助手给出多款商品建议，**Then** 展示推荐清单卡，按推荐理由或适用场景分组。
4. **Given** 用户询问"这个配方里的鸡肉粉是什么"，**When** AI助手解释成分，**Then** 展示成分/营养解读卡，说明含义、可能优点、注意事项和适用宠物。
5. **Given** 用户问题缺少关键条件，**When** AI助手无法可靠推荐，**Then** 展示追问卡，引导用户补充宠物年龄、预算、品牌偏好或健康状况。

### User Story 3 - 探索并落地AI助手新增能力 (Priority: P2)

产品团队希望在优化现有能力之外，系统性探索AI助手在宠物用品和宠物知识领域可新增的能力，并将可验证、有用户价值的能力纳入AI助手体验。首个面向用户落地的新增能力为"换粮计划"，其他候选能力可包括商品替代推荐、喂养量估算、用品购买清单、成分风险解释等。

**Why this priority**: 新能力探索可以扩大AI助手的差异化价值，但必须建立在P1基础问答可靠的前提上，避免把不成熟能力直接暴露给用户。

**Independent Test**: 从候选能力中选择至少两个进行体验验证，每个候选能力都有明确触发场景、用户价值、成功/失败表现；其中"换粮计划"必须落地为可面向用户演示的能力。

**Acceptance Scenarios**:

1. **Given** 产品团队提交候选能力清单，**When** 进入能力评估，**Then** 每个候选能力应说明适用问题、用户价值、所需输入、输出形式和不可用时的降级方式。
2. **Given** 某个候选能力缺少可靠数据或存在明显风险，**When** 完成评估，**Then** 该能力应标记为暂缓，并记录暂缓原因。
3. **Given** 用户询问"怎么从旧粮换到新粮"并提供宠物阶段、当前粮、新粮和肠胃情况，**When** AI助手触发换粮计划能力，**Then** 应给出分阶段换粮建议、观察要点和异常时停止/就医提示。
4. **Given** 用户未提供当前粮、新粮或宠物肠胃情况，**When** AI助手识别为换粮计划场景，**Then** 应优先追问缺失信息，而不是直接生成完整计划。
5. **Given** 新能力输出不确定，**When** AI助手回复，**Then** 应明确说明依据和限制，不将推测包装成确定结论。

### User Story 4 - 后台Dream长期记忆整理 (Priority: P2)

系统在用户产生新对话后，每日批次整理新增对话内容，提取对AI助手长期有用的信息，形成该用户的长期记忆，并确保有效长期信息在24小时内反映到记忆中。长期记忆应聚焦必要内容，例如常问问题、宠物状况、偏好、预算、过敏或不适反应，并控制在500字符以内。

**Why this priority**: 长期记忆让AI助手能从一次性问答变成持续了解用户和宠物的助手，是个性化体验的关键基础。

**Independent Test**: 构造一组包含宠物年龄、健康状况、用品偏好和无关闲聊的新增对话，触发记忆整理后验证长期记忆只保留必要信息、内容准确且不超过500字符。

**Acceptance Scenarios**:

1. **Given** 用户在新对话中提到"我家布偶猫6个月，最近换粮容易软便"，**When** 后台每日批次完成记忆整理，**Then** 用户长期记忆应在24小时内包含宠物种类、年龄阶段和软便/换粮敏感信息。
2. **Given** 用户对话中包含临时闲聊或一次性问题，**When** 后台整理长期记忆，**Then** 不应把无长期价值的信息写入记忆。
3. **Given** 用户长期记忆已接近500字符，**When** 新增信息需要写入，**Then** 系统应优先保留当前更重要、更稳定的信息，并压缩或移除过时信息。
4. **Given** 新对话没有可沉淀信息，**When** 后台执行整理，**Then** 长期记忆保持不变。
5. **Given** 记忆整理失败，**When** 用户继续使用AI助手，**Then** 现有对话功能不受影响，旧记忆保持可用。

### User Story 5 - 我的页查看和修改AI印象 (Priority: P2)

用户可以在"我的"页面查看"AI助手对我的印象"，理解AI长期记忆中保存了哪些内容。长期记忆按宠物状况、偏好预算、常问问题、注意事项分组展示和编辑，并在对用户展示时保持500字符以内。系统只保留当前有效记忆和最近更新时间，不向用户展示历史版本。用户修改后的记忆应优先作为后续AI助手个性化回答的依据。

**Why this priority**: 长期记忆涉及用户隐私和信任。用户必须能看见、纠正和控制AI对自己的理解，否则个性化能力会带来不透明感。

**Independent Test**: 用户进入"我的"页面查看AI印象，在宠物状况、偏好预算、常问问题或注意事项分组中编辑一条错误信息并保存，再次向AI提问时验证AI使用修改后的记忆而不是旧记忆。

**Acceptance Scenarios**:

1. **Given** 用户已有长期记忆，**When** 进入"我的"页面并点击"AI助手对我的印象"，**Then** 页面按宠物状况、偏好预算、常问问题、注意事项展示500字符以内的记忆内容、最近更新时间和编辑入口。
2. **Given** 用户发现记忆中宠物年龄错误，**When** 在宠物状况分组中修改并保存，**Then** 页面立即展示新内容，后续AI回复应以用户修改后的内容为准。
3. **Given** 用户不希望继续保留长期记忆，**When** 点击清空或暂停记录，**Then** AI助手不再使用已清空内容，并清楚展示当前状态。
4. **Given** 用户尚无长期记忆，**When** 打开AI印象页，**Then** 展示空状态，说明AI尚未形成可展示的长期印象。

### Edge Cases

- 用户未登录时，不生成用户长期记忆，也不展示"AI助手对我的印象"入口。
- 对话内容中出现地址、联系方式、支付信息等与宠物服务无关的敏感个人信息时，不写入长期记忆。
- 用户手动修改长期记忆后，后续自动整理不得静默覆盖用户明确修正的内容。
- 多只宠物信息混杂时，长期记忆应按宠物区分，避免把症状、偏好或年龄归到错误宠物。
- 用户表达"刚才说错了"或更正宠物状况时，长期记忆应优先采用最新明确更正。
- 商品数据缺失、下架或匹配置信不足时，AI不得伪造商品卡片，应说明不可推荐或改用追问/通用建议。
- 商品卡片内容过长时，优先展示决策必要信息，避免遮挡或挤压主要回复。
- 宠物健康问题涉及急症、用药、剂量或诊断时，AI应给出风险提示并建议咨询兽医。
- 长期记忆超过500字符时，保存前必须压缩到限制以内。
- 后台整理与用户手动编辑同时发生时，以用户最近一次保存的内容为准。
- 长期记忆被自动整理、用户编辑或清空后，用户侧只展示当前有效内容和最近更新时间，不提供历史版本查看或恢复。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: AI助手 MUST 能识别宠物用品选购、宠物知识咨询、商品比较、成分/营养解读、健康风险提示和信息不足追问等主要意图。
- **FR-002**: AI助手 MUST 优化现有工具使用效果，在产品问答中优先使用已有商品、评价、价格、分类、宠物档案和历史上下文信息。
- **FR-003**: AI助手 MUST 在缺少关键条件或商品数据不足时明确追问或说明限制，不得编造商品、评价、价格或宠物状况。
- **FR-004**: AI助手 MUST 对宠物健康风险类问题给出安全边界提示，不得替代兽医诊断或处方。
- **FR-005**: 系统 MUST 建立AI助手新增能力的评估流程，每个候选能力必须记录适用场景、用户价值、必要输入、输出形式、风险和降级方式。
- **FR-006**: 本特性 MUST 至少评估两个新增能力候选，并将"换粮计划"作为首个可被用户触发和验证的新增能力落地。
- **FR-007**: 产品问答 MUST 支持多种卡片类型，至少包括SPU单品卡、商品对比卡、推荐清单卡、成分/营养解读卡和追问卡。
- **FR-008**: 优化后的SPU单品卡 MUST 展示品牌、商品名、适用宠物、分类、价格区间、核心优点、注意点和进入详情入口。
- **FR-009**: 商品对比卡 MUST 支持至少两个商品的并排比较，包含适用场景、价格区间、主要优缺点和推荐结论。
- **FR-010**: 推荐清单卡 MUST 能按用户问题中的预算、宠物阶段、用品类型或偏好展示多个候选商品及推荐理由。
- **FR-011**: 成分/营养解读卡 MUST 解释关键成分或营养指标的含义、可能优点、注意事项和适用宠物。
- **FR-012**: 追问卡 MUST 在无法可靠推荐时引导用户补充必要条件，例如宠物年龄、体重、预算、品牌偏好、过敏或不适反应。
- **FR-013**: 系统 MUST 每日批次整理用户新增对话，提取对后续服务有长期价值的信息，形成用户级AI长期记忆，并以24小时内更新为目标。
- **FR-014**: 长期记忆 MUST 控制在500字符以内，并按宠物状况、偏好预算、常问问题、注意事项四类组织必要内容。
- **FR-015**: 长期记忆 MUST 排除无长期价值的闲聊、一次性任务、未经确认的推测和与宠物服务无关的敏感个人信息。
- **FR-016**: AI助手 MUST 在后续对话中使用该用户的长期记忆进行个性化回答，并在相关时体现"基于你的宠物情况"的上下文。
- **FR-017**: "我的"页面 MUST 提供"AI助手对我的印象"入口，登录用户可按宠物状况、偏好预算、常问问题、注意事项查看长期记忆内容和最近更新时间。
- **FR-018**: 用户 MUST 能按分类手动编辑并保存长期记忆，保存后的内容立即成为后续AI助手个性化回答的优先依据。
- **FR-019**: 长期记忆 MUST 对登录用户默认开启，并在AI助手和"我的"页面展示清晰说明；用户可随时清空长期记忆或暂停继续记录，暂停后不再从新增对话中沉淀长期记忆，直到用户恢复。
- **FR-020**: 系统 MUST 保护用户手动修改的记忆内容，自动整理不得静默覆盖用户明确修正的信息。
- **FR-021**: 系统 MUST 只向用户保留和展示当前有效长期记忆及最近更新时间，不提供长期记忆历史版本查看或恢复能力。

### Key Entities

- **Assistant Capability（AI助手能力）**: 表示AI助手可支持的一类能力，如商品比较、成分解读、换粮计划或购买清单。包含适用场景、用户价值、所需输入、输出形式、风险和当前状态。
- **Product Answer Card（商品问答卡片）**: AI回复中的结构化展示单元。可表示单品、多个商品对比、推荐清单、成分/营养解读或追问信息。
- **AI Long-Term Memory（AI长期记忆）**: 面向单个用户的500字符以内摘要，按宠物状况、偏好预算、常问问题、注意事项组织，记录AI助手后续服务所需的必要长期信息；用户侧只保留当前有效内容和最近更新时间。
- **Memory Update（记忆更新）**: 一次从新增对话或用户手动编辑产生的长期记忆变化，产生新的当前有效内容和最近更新时间，不要求向用户保留可查看的历史版本。
- **User（用户）**: 已有实体。长期记忆与用户绑定，用户可查看、编辑、清空或暂停记录。
- **Chat Conversation（对话）**: 已有实体。后台Dream整理机制从用户新增对话中提取可沉淀信息。
- **SPU（标准商品单元）**: 已有实体。AI商品问答卡片引用SPU及其相关评价、价格、分类和适用宠物信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 覆盖宠物用品、宠物知识、商品比较、成分解读和健康风险的测试问题中，80%以上的AI回复被评审为"相关且可执行"。
- **SC-002**: 对可匹配到商品数据的产品类问题，90%以上能展示与用户意图匹配的商品卡片类型。
- **SC-003**: 用户在产品问答中从AI回复进入商品详情或继续追问的比例较优化前提升20%以上。
- **SC-004**: 90%的用户能在1分钟内从"我的"页面找到并完成长期记忆查看。
- **SC-005**: 90%的用户能在1分钟内完成长期记忆编辑并保存。
- **SC-006**: 新增对话中的有效长期信息在24小时内反映到用户长期记忆中的成功率达到95%以上。
- **SC-007**: 100%的长期记忆展示内容不超过500字符。
- **SC-008**: 长期记忆抽取评审中，错误归因、过时信息或敏感无关信息写入率低于2%。
- **SC-009**: 对已启用长期记忆的用户，AI助手个性化回答满意度较无记忆状态提升25%以上。

## Assumptions

- 现有AI助手、用户登录、宠物档案、SPU商品和评价数据能力可作为本特性的基础。
- 长期记忆以用户为单位维护，而不是以单个会话为单位维护。
- 长期记忆默认使用中文摘要，500字符指最终展示给用户的中文内容长度。
- 长期记忆对登录用户默认开启，但用户可在"我的"页面查看说明并随时关闭或清空。
